= Ration Kiosk

== Challenge's context

[quote]
A food-ration distribution kiosk accepts requests over standard input.
It is a statically linked binary with no modern exploit mitigations.
Somewhere inside the binary is a function that decrypts and prints the flag.
The normal request-handling path never calls it.
The function expects two arguments that are stored as globals.
The kiosk reads your input into a fixed-size buffer.

From this we know there's probably a stack overflow that should allow us to call a function that decrypts and prints the flag.
This function takes global variables as arguments.

That's the overflow vulnerability.

== What's being overwritten?

After `call handle_request` in `main()` and reserving the 80 bytes, the stack looks as follows:

----
|                 | 
|-----------------|
| Next RIP @ main |  |
|-----------------|  | stack
|  RBP from main  |  | growth
|-----------------|  |
|                 |  v
| 80-byte buffer  |
|                 |
|-----------------|
----

So the overflow will first overwrite ``main``'s saved RBP and RIP.
Then, when `leave` (equivalent to `mov rsp, rbp; pop rbp`) is executed, the stack pointer is restored (freeing the 80 bytes), and the ``main``'s RBP is restored form the stack to RBP.
This explains why in GDB we saw part of the overflow string in RBP.

The overflow next overwrites the saved RIP.
When `ret` is executed we end up jumping to an address controlled by us.
Since previously we wrote an invalid (non-mapped) address to it (part of the string), the program can no longer continue and it segfaults.
If we write a valid address, we can control the execution's flow.

== Calling `give_flag()`

All we need to do is overwrite ``main()``'s stored RIP on the stack with the address from `give_flag()` so that when `ret` is executed in `handle_request()` we jump to `give_flag()` rather than `main`.

----
$ python
>>> from pwnlib.util.packing import *
>>> b =  p8(0)*80          # buffer
>>> b += p64(0)            # rbp
>>> b += p64(0x004017b9)   # rip
>>> open("payload.raw", "wb").write(b)
----

With that, the stack will contain:

----
|                 | 
|-----------------|
|    give_flag    |  |
|-----------------|  | stack
|       0x0       |  | growth
|-----------------|  |
|                 |  v
| 80-byte buffer  |
|  (zero filled)  |
|-----------------|
----

Let's try the overflow:

* The program no longer segfaults
* But it prints some gibberish, not the flag
** This is natural... because we XORed `flag_ct` with unspecified RDI and RSI arguments
